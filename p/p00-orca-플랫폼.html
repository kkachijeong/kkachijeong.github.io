Orca · 로스트아크 게임로그 데이터 플랫폼

로스트아크 게임로그를 받아 저장하고 운영툴과 분석 환경에서 조회하게 하는 사내 데이터 플랫폼

기간
2018 ~ 현재
역할

  • Kafka

  • HBase
  • PPhoenix
  • HDFS
  • IIceberg

  • Airflow
  • Cloudera
  • AAmbari

무엇을

로스트아크의 게임로그를 받아 저장하고, 운영기획·데이터분석·레벨기획·CS/GM 등 여러 부서가 운영툴과 분석 환경에서 조회하는 플랫폼입니다. 가장 많던 때는 하루 십수억 행이 들어왔고, 로그 타입은 수백 종입니다. 지금도 하루 수억 행이 들어옵니다.

층 구성 맡은 프로젝트
적재 Kafka → OrcaEater(Spark Streaming, 20초 배치) → HBase / Phoenix / Iceberg
조회 운영툴 → Orca SDK → HBase·Phoenix, Spark(Livy), Trino/Iceberg Orca 게임로그 조회 SDK
운영 HBase 클러스터, Airflow 운영 DAG 80종 이상 HBase Manager
레이크 Orca Lake: Iceberg + Trino 기반 hot 계층 데이터레이크 Orca Lake 권한 체계와 로그 관측
서비스 실시간 이상탐지, 분석 환경 사용 이력 감사 Thunder Eye, 분석 환경 감사

왜

2018년 2월 팀에 합류했을 때 Orca는 적재기가 HDFS에 로그를 쓰는 단계였습니다. 지금은 보상·이벤트 대상자 추출, 봇·핵 탐지의 제재 근거 작성처럼 로스트아크 게임 데이터를 쓰는 일 대부분이 이 플랫폼 위에서 돌아갑니다.

어떻게

  • 클러스터 상시 운영 (4인 중 1인)
    • 노드 증설·디스크 교체 대응, HDFS 용량 관리와 오래된 데이터 삭제, 설정 튜닝
    • 장애 당번·알람 대응은 팀 전체가 분담
  • 새 적재 요청 설정 단독 처리
    • Kafka 토픽 생성, HBase·Phoenix 테이블 생성, 적재기 설정 파일에 토픽과 테이블 등록
  • 게임로그 저장 구조 설계 참여 (2인 중 1인)
    • 계정 단위 조회용 HBase 스키마와 기간 조회용 Phoenix 테이블 설계
  • 차세대 클러스터 배포 도구 전환 (4인 중 1인)
    • 라이브 중인 Cloudera(CDH 5.14) 클러스터는 서비스 중단 부담과 상위 버전 유료 구독 문제로 유지, 차세대 Orca Lake는 Ambari로 새로 구성

결과

  • 수십 대 규모·PB급 HDFS 클러스터와 10여 대·수백 TB 규모 Orca Lake 운영
  • 조회 SDK, HBase 운영 자동화, Orca Lake 권한·로그 관측, 실시간 이상탐지를 이 플랫폼 위에서 개발
  • Airflow 정기 작업 단독 운영, 운영팀 요청 데이터 추출과 백업(S3·Glacier) 2인 중 1인
  • 2026-09부터 신규 IDC 클러스터로 이전 중, 신규 서버군에는 HBase를 올리지 않아 조회 경로를 Iceberg/Trino로 전환
