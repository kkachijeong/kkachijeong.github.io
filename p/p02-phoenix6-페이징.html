조회 SDK 모바일 이전과 Phoenix 키 기반 페이징 전환

PC와 모바일 운영툴이 같은 조회 SDK를 쓰도록 옮기고, 모바일 EMR에서 멈춘 대량 조회를 키 기반 페이징으로 바꾼 일

기간
2024 ~ 2026
역할
단독 (Orca SDK 설계·개발·운영 담당)
  • C#/.NET 6
  • .NET Framework 4.6.1
  • PPhoenix Query Server
  • AWS EMR
  • Llog4net
  • SSerilog

무엇을

모바일 운영툴은 .NET 6, PC 운영툴은 .NET Framework 4.6.1이라 같은 조회 SDK가 두 환경을 모두 지원해야 했습니다. 모바일 EMR의 Phoenix에서는 SDK가 대량 조회에 쓰던 커서(DECLARE/OPEN/FETCH)가 결과를 만들지 못해, 커서를 버리고 키 기반 페이징으로 바꿨습니다.

왜

오픈소스 코드까지 분석해 이 환경에서 커서가 동작하지 않는다는 것을 확인했습니다. 고치려면 EMR에 들어 있는 Phoenix를 수정해야 했고 그건 현실적인 선택지가 아니어서, 조회 방식을 바꿨습니다.

어떻게

  • 로깅 경계 분리: 모바일은 Serilog, PC는 log4net이라 로그가 남지 않던 문제를 SDK 안의 delegate 기반 Logger로 해결, 어느 로깅 프레임워크든 연결 가능
  • 멀티 타겟 빌드 검토 후 Perforce 업로드 구조와 의존성 차이로 포기, 모바일 EMR 전용 프로젝트 분리 (PC·모바일·북미 세 갈래 빌드)
  • 커서 대신 WHERE 키 > 마지막 키 ORDER BY ... LIMIT n 키 기반 페이징 구현, 서버 쪽 커서 상태에 의존하지 않는 구조
  • .NET 6에서 깨진 Livy 클라이언트의 BinaryFormatter 직렬화를 JSON으로 교체

결과

  • 누락·중복 없음과 응답시간 기존 대비 ±5% 수준을 확인한 뒤 모바일 EMR SDK 전환
  • 대량 조회가 서버 쪽 커서 동작에 묶이지 않아 Phoenix 서버·클라이언트 버전 차이의 영향에서 분리
