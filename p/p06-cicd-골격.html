실 공용 빌드·배포 파이프라인

실(室)의 모든 팀이 빌드·배포 설정을 나에게 요청하지 않고 직접 할 수 있게 다시 세운 공용 파이프라인

기간
2019 ~ 현재
역할
단독
  • Jenkins
  • GitLab CI
  • Perforce
  • PPowerShell
  • Docker
  • Harbor
  • AWS S3

무엇을

로스트아크 PC(국내·해외)와 모바일의 인증·로그·웹 서비스를 빌드해 개발망과 IDC망에 배포하는 파이프라인입니다. 2019년에 기존 파이프라인과 별개로 거의 새로 만들었고, 이후 국가·퍼블리셔와 클라우드 환경이 늘 때마다 넓혔습니다.

왜

실의 모든 팀이 빌드·배포 설정을 나에게 요청했습니다. 그 요청을 받지 않고 각 팀이 직접 설정할 수 있게 하려고 구조를 완전히 바꿨습니다. 환경은 개발망·IDC망마다 DEV·QA·CBT·LIVE가 있고 해외 퍼블리셔별 배포 경로가 따로 있어, IDC 환경 분리까지 함께 풀어야 했습니다.

어떻게

  • 파일이 Git → 빌드 서버 → 배포 서버 → IDC망 배포 서버 → 대상 서버로 여러 번 옮겨지는 구조라, 설정 값을 뺀 최종 배포본과 빌드본을 해시로 비교하는 무결성 검증 추가
  • cherry-pick 형상관리에서 누락 커밋이 쌓여 릴리스 때 대량 병합 충돌이 나던 것을 브랜치 주기 백업·재생성 자동화로 차단, 이후 GitLab CI로 이전
  • Jenkins Job 안에 직접 쓰여 개발망·IDC망끼리 어긋나던 배포 스크립트를 Git으로 옮기고 배포 스크립트 전용 저장소 분리
  • 2026년 VPC 분리에 맞춰 AWS Docker 서비스 배포를 직접 SSH에서 S3 경유(대상 서버가 가져가는 방식)로 전환

결과

  • 북미·중국·러시아 등 국가·퍼블리셔 전용 빌드와 모바일 전용 빌드 서버까지 배포 매트릭스 확장
  • 신규 IDC Docker 배포에 대수 단위로 묶는 병렬 배포 잡 추가 (기존 순차 배포가 오래 걸려 대수 단위로 묶음, 8대 시험 배포 완료)
