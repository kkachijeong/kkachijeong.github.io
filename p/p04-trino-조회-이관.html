게임로그 조회 경로 Iceberg/Trino 전환

HBase·Phoenix 두 벌로 쌓이던 게임로그 조회를 Iceberg/Trino 한 경로로 옮기고, 옮겨도 결과가 같다는 것을 실사용 조건으로 증명한 전환

기간
2026 ~ 현재
역할
2인 중 조회 경로(SDK·운영툴 연결·검증) 담당
  • C#/.NET
  • Trino
  • IIceberg

무엇을

운영툴의 게임로그 조회를 HBase/Phoenix에서 Iceberg 테이블을 Trino로 조회하는 경로로 옮긴 일입니다. 조회 SDK의 세 번째 저장소 전환이고, 2인 중 조회 경로를 맡았습니다.

왜

같은 데이터가 HBase와 Phoenix에 두 벌로 쌓였고, Phoenix는 업데이트가 잘 안 되고 검색 오류가 잦았습니다. 신규 IDC 이전은 구 경로를 걷어내는 시점을 정했을 뿐입니다. 신규 서버군에는 HBase·Phoenix를 올리지 않아, 서버가 바뀌면 구 경로로는 조회 자체가 불가능해집니다.

어떻게

  • 병행 이식
    • 모바일 SDK에 있던 Trino 클라이언트를 PC SDK에 같은 구조로 이식, 기존 HBase/Phoenix 경로는 유지해 운영툴이 조회 경로 선택
  • 조회 제한 값을 벤치마크로 결정
    • 조회 건수·검색 기간·로그 타입 수·월드 수 축으로 라이브 벤치마크, 최대 1만 건·365일을 SDK 정책 상수로 확정
  • Iceberg/Trino 전환 정합성 검증 체계 설계
    • 실사용 검색 로그 분포에서 빈번 조건·고부하 조건 기준으로 검증 케이스 선정
    • 판정 기준 사전 정의: 페이지 끝까지 행 키 집합 대조, 페이지당 3회 중앙값
    • 속도 비교용이 아닌 케이스를 따로 둠: Iceberg에 데이터가 빠진 구간의 결과 차이 확인, 화면 동작 차이 확인
  • 대량 내보내기의 OFFSET 페이징 폐기
    • 뒤 페이지일수록 앞부분을 다시 읽고 정렬 키 동률 경계에서 행 중복·누락이 생기는 문제
    • 쿼리를 한 번 던지고 Trino 응답의 다음 주소를 따라 5,000건씩 넘기는 방식으로 교체, 중간에 멈추면 쿼리 취소, 기존 내보내기 인터페이스는 그대로 유지

결과

  • 속도 측정 케이스 전건 행 키 일치, 93%에서 Trino 응답 우위 확인 후 QA 환경 Trino 단독 전환 (2026-10)
  • QA 환경이 HBase/Phoenix 없이 Trino만으로 운영툴이 도는 첫 환경
  • LIVE 운영툴 화면은 백엔드개발팀이 이 SDK와 가이드를 참조해 Trino 조회를 병행 경로로 반영 (2026-08), LIVE 단독 전환은 운영툴 적용만 남은 상태
