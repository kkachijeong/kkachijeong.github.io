분석 환경 사용 이력 감사 Zeppelin Watcher

분석 환경에서 누가 어떤 민감 로그를 조회했는지 남기는 감사 기록

기간
2024 ~ 현재
역할
단독 (ELK 자체 운영은 인프라팀)
  • Python
  • Redis
  • Solr
  • Elasticsearch
  • Kibana
  • MySQL
  • ZZeppelin
  • Docker

무엇을

분석 환경(Zeppelin)에서 누가 어떤 노트로 어떤 스크립트를 실행했는지 기록하고, 운영툴 Orca Eye에서 검색하게 한 감사 시스템입니다. 설계부터 저장소 전환, 운영 장애 대응까지 혼자 맡았습니다.

왜

정기 보안 감사와 개인정보 점검에서 "제플린에서 누가 어떤 민감 로그를 조회했는지 추적할 수 없다"는 지적을 받았습니다.

어떻게

  • Zeppelin 소스는 고치지 않고 로그 폴더를 감시하는 별도 Python 데몬으로 분리
  • 작업 시작·종료 등 여러 형태의 로그에서 정규식으로 사용자·노트·문단 id 추출, 그 id로 노트북 JSON을 다시 찾아 실제 실행 스크립트까지 기록
  • 저장소 Redis → Solr → ELK 전환
    • Redis → Solr: 이중 기록과 설정 기반 조회 선택으로 한 번에 갈아타지 않고 전환
    • Solr → ELK: IDC 이전 때 Solr를 다시 세우지 않고 인프라팀 운영 ELK로 흡수, 이벤트는 데이터스트림(3년 보존), 사용자 상태는 일반 인덱스로 분리
    • 알림 규칙 같은 설정값은 운영툴 MySQL로 이전

결과

  • 2024-06부터 2026-08까지 LIVE 감사 기록 축적
  • LIVE는 감사 이력이 끊기지 않게 Solr 이력을 ELK로 이관, 원본 값이 손상된 2건만 갭으로 남김
  • Zeppelin private 모드 조회는 Zeppelin 자체 한계로 기록되지 않아 private 여부를 화면에 표시하는 것으로 절충
