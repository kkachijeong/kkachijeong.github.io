Orca 게임로그 조회 SDK

Orca에 적재한 게임로그를 운영툴에서 검색할 수 있게 하는 조회 SDK

기간
2018 ~ 현재
역할
설계·개발·운영 단독 (2026 Iceberg/Trino 전환은 2인 중 조회 경로 담당)
  • C#/.NET
  • HBase
  • PPhoenix
  • ZZookeeper
  • Spark(Livy)
  • Trino
  • IIceberg

무엇을

Orca에 적재한 게임로그를 운영툴에서 검색할 수 있게 하는 조회 SDK입니다. 2018년에 처음 만들어 지금까지 혼자 운영하고 있습니다. 같은 SDK가 북미·유럽 리전 운영툴에도 배포됐습니다.

왜

목적은 Orca가 적재한 데이터를 운영툴에서 검색할 수 있게 하는 것입니다. 2018년 런칭 준비기에 HBase Thrift 클라이언트와 Phoenix 클라이언트를 .NET에서 처음부터 구현해야 했고, 운영툴은 계정 하나의 로그를 페이지 단위로 넘겨 보는 화면이라 페이징이 필수였습니다.

어떻게

  • 조회 저장소 3세대 전환 (HBase/Phoenix → Spark(Livy) → Iceberg/Trino)
    • Phoenix 장기간·대량 검색 불가 문제로 Spark(Livy) 조회 경로 추가
    • HBase·Phoenix 이중 적재와 잦은 Phoenix 검색 오류 해소를 위해 Iceberg/Trino 전환
    • 기존 경로를 유지한 채 신규 경로를 나란히 붙이는 병행 방식으로 전환
  • 초기 조회 구조 설계
    • HBase 페이징에 PageFilter 대신 스캔 후 Limit + 마지막 행 키를 다음 시작점으로 넘기는 방식 채택 (PageFilter는 리전마다 N건을 돌려줘 페이지 결과 수가 어긋남)
    • Phoenix 조회 분산은 LB 장비 대신 Zookeeper의 살아 있는 Query Server 목록을 SDK가 직접 읽는 방식 (검색만을 위한 LB 장비는 과하다고 판단)
  • Zookeeper 세션 장애 대응
    • 세션이 끊기면 서버 목록을 못 받아 조회 전체가 막히는 문제가 여러 해 재발, 강제 재현이 안 돼 재발을 전제로 의심 지점에 로그 보강
    • 쌓아 온 로그로 클라이언트 생성 전에 콜백이 실행되는 동시성 버그 분석
    • 오픈소스 ZookeeperNet의 세션 종료 버그를 라이브러리에서 직접 수정, 라이브 환경 버전이 바뀌지 않아 사내 포크로 유지
  • Iceberg/Trino 전환 정합성 검증 체계 설계
    • 실사용 검색 로그 분포에서 빈번 조건·고부하 조건 기준으로 검증 케이스 선정
    • 판정 기준 사전 정의: 페이지 끝까지 행 키 집합 대조, 페이지당 3회 중앙값

결과

  • 속도 측정 케이스 전건 행 키 일치, 93%에서 Trino 응답 우위 확인 후 QA 환경 Trino 단독 전환 (2026-10)
  • 운영툴 전용 HBase 테이블 이관 및 대사 (단독)
    • 운영툴 전용 메일 수령 로그 테이블 수억 건 이관, 검수 대상을 월→일→시간→분 단위로 좁혀 차이 1건을 레거시 적재 결손으로 확정
    • 체크섬 불일치 건의 원문 바이트 단위 대조로 적재 코드의 재직렬화 저장 문제(표본 35%) 규명
  • Zookeeper 세션 만료의 근본 원인은 아직 확정하지 못함
