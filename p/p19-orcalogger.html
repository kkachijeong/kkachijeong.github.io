OrcaLogger 로깅 SDK와 Hub 종료 처리

Ludy 서비스의 게임로그를 Orca로 보내는 log4net 기반 로깅 SDK. Hub 종료 처리와 Redis 구독 조사는 같은 서비스의 별건

기간
2019 ~ 2024
역할
단독
  • C#/.NET
  • Llog4net
  • Kafka Producer
  • WWindows 서비스
  • Redis

무엇을

인증·회원 서비스 Ludy에서 나는 게임로그를 Orca로 보내는 로깅 SDK OrcaLogger를 만들고 운영했습니다. 같은 서비스 묶음의 Hub 종료 처리와 Redis 클러스터 구독 조사는 성격이 다른 별건이라 따로 적습니다.

왜

OrcaLogger는 Ludy 서비스가 Orca 적재 경로인 Kafka로 로그를 보내는 출구입니다. Hub 쪽은 강제 종료 때 Kafka 커밋이 보장되지 않아 이벤트가 중복 발생하는 문제가 있었습니다.

어떻게

  • log4net 기반 Kafka Appender에 파일 폴백 SubAppender를 두고, JSON payload 검증과 로그 타입 대역 정의
  • 운영 중 장애 원인 추적과 수정: Reactive 비동기 처리 버그, 어셈블리 미참조로 인한 멈춤, 대량 발행 시 큐 초과, 글자 수 초과 로그로 인한 적재 장애, 설정 리로드 시 Appender 재초기화 버그
  • Hub 종료(별건): 콘솔 제어 핸들러, 창 닫기 메시지, taskkill 신호 수신, 자식 프로세스 분리가 Windows 서비스·콘솔 환경 제약으로 모두 막혀, 특정 파일을 만들거나 바꾸면 Hub가 감지해 스스로 종료하는 파일 신호 방식 채택. 배포 스크립트에서 제어 가능한 점을 우선
  • Redis 구독 조사(별건): 라이브러리 3종 비교로 Redis 클러스터의 keyspace notification이 노드별로만 발생해 구독자 하나로는 이벤트가 빠지는 것을 확인, 노드마다 따로 연결해 구독하는 방식을 해법으로 정리

결과

  • Hub 강제 종료 대신 파일 신호로 정상 종료해 Kafka 커밋 누락으로 인한 이벤트 중복을 해결
  • 웹팀 확산을 위해 의존성 분리와 설정 위치 변경을 검토했으나 웹팀 자체 대응으로 보류
