Orca Lake 데이터레이크 구축과 이전

게임로그를 Iceberg로 모아 Trino로 바로 조회하는 hot 계층 데이터레이크의 캐시·검색 계층과 수집·이전

기간
2025 ~ 현재
역할
여러 명 중 캐시·검색 계층(Alluxio, Solr), 게임로그 밖 데이터 수집, 분석 코드 이전, 신규 IDC 이전 담당 (클러스터 설치, 테이블 포맷 선정, 게임로그 Iceberg 테이블 설계·적재는 다른 담당자)
  • AAlluxio
  • Solr
  • IIceberg
  • Trino
  • ZZeppelin
  • Spark
  • Perforce
  • AWS S3
  • Docker

무엇을

Orca Lake는 게임로그를 Iceberg로 모아 Trino로 바로 조회하는 hot 계층 데이터레이크입니다(10여 대, 수백 TB). 클러스터 설치, 테이블 포맷 선정, 게임로그 테이블 설계와 적재는 다른 담당자들이 맡았고, 저는 캐시·검색 계층과 게임로그 밖 데이터 수집, 기존 분석 코드 이전, 신규 IDC 이전을 맡았습니다.

왜

게임로그를 한곳에 모아 Trino로 바로 조회할 hot 계층을 두는 것이 목적이었습니다. 접근 권한 체계와 클러스터 로그 수집도 이 레이크 위에서 혼자 맡았고, 각각 따로 정리했습니다.

어떻게

  • 캐시·검색 계층
    • Alluxio 캐시 계층 구성·튜닝
    • Solr 기반 검색 계층(Queries Layer) 설계·구축·튜닝, Solr 기술 가이드 작성
  • 게임로그 밖 데이터 수집
    • Perforce 소스코드·메타데이터 수집 파이프라인
    • 서버 파일시스템 → 원시 계층 ETL, S3 백업·복원 자동화
  • 기존 분석 코드 이전
    • 기존 Zeppelin 분석 코드 Orca Lake 이전, 이전 중 드러난 밸런스 추출 버그 2건(정수 범위 초과, 맵 필터 조건 차이) 수정
    • 외부 파일 업로드 경로(SFTPGo) 인증 방식 분석과 업로드 가이드 보완
  • 신규 IDC 이전(2026-09~): 마스터 3대 Docker 설치, 데이터노드는 디스크 영향 논의 뒤 로그 수집(Filebeat) 배포를 위해 포함

결과

  • 기존 Zeppelin 분석 코드를 Orca Lake에서 돌도록 이전
  • 게임로그 밖 데이터(소스코드 메타데이터, 서버 파일)를 레이크 원시 계층으로 수집
  • Orca Lake에서 검증한 구성을 신규 IDC 서버군으로 옮기는 중
